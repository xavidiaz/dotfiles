# dotfiles

Personal config for an Omarchy (Arch + Hyprland) desktop, managed with [GNU Stow](https://www.gnu.org/software/stow/).
Each top-level directory is a Stow "package" that mirrors its target location under `$HOME`.

## Packages

App configs (`~/.config/<name>`): `hypr`, `alacritty`, `foot`, `ghostty`, `kitty`, `nvim`, `tmux`, `btop`,
`lazygit`, `herdr`, `hyprmoncfg`, `mise`, `wally`, `voxtype`, `xournalpp`, `autostart`,
`git` (global git config), `mimeapps`, `starship`, `bat`, `glow`, `darky` (see below), `chawan` (JS/cookies off, enabled per site), `tuios` (leader Ctrl+Space),
`fcitx5` (input-method toggle moved off Ctrl+Space so it doesn't steal the tuios/tmux prefix).

Home-root files: `bash` (`.bashrc`, `.bash_profile`, `.profile`, `.bash_logout`), `codespaces` (`~/.ssh/config.d/codespaces`:
SSH entries for the CodeSpaces dev containers, generated by `cs` on the host; see below).

Partial package: `omarchy` — only the small user-facing files (`branding`, `defaults`, `hooks`, `light-dark.conf`,
`shell.json`, `omasettings.json`). The `plugins/` cache, `themes/`, `themed/`,
and `extensions/` are left as local, machine-generated state and are NOT tracked here.
Plugins are instead listed in `omarchy-plugins.txt` (`<id> <git-url>`); `install.sh` runs
`omarchy plugin add` for any that are missing and `omarchy plugin update` for the rest, so every
machine gets the same, current plugins that `shell.json` references.

`darky`: Darky's settings (`~/.local/state/darky/settings.json`: theme pair, schedule and
location, so every machine switches the same themes at the same sunrise/sunset), plus a systemd
watcher. Darky saves by renaming a new file over the old one, which breaks a symlink, so
`darky-relink.path` (and `hooks/darky.d/relink-dotfiles.hook` after each switch) moves the new
contents into the repo and puts the symlinks back, for `settings.json` and `omarchy`'s
`light-dark.conf`.

Not included:

- `gh` (GitHub CLI config) — just run `gh auth login` on the new machine instead.
- Browser profiles (Brave/Chrome/Edge/Chromium) — not dotfiles, don't belong in git.

## `claude-mods/`

Not a Stow package: a Claude Code plugin marketplace holding personal mods, which `install.sh`
adds and installs from (`claude plugin marketplace add ~/dotfiles/claude-mods`, then
`claude plugin install <mod>@dotfiles-mods --scope user`). Claude Code runs a plugin from a folder
marketplace in place, so an edit here applies after `/reload-plugins`. Currently:

- `code-cards`: code blocks in replies drawn as Obsidian-style cards with a Copy button.

## Pi (`pi-settings.json`)

The [Pi coding agent](https://pi.dev) comes from Omarchy's mise tools; `mise/` pins it
(`pi = "1.6.1"`, so Omarchy's 4-hourly `latest` doesn't move it) and Node (`26.13.1`).
Pi rewrites `~/.pi/agent/settings.json` itself, so it isn't stowed: `install.sh` merges
`pi-settings.json` into it with `jq`, then runs `pi update --extensions` to install the packages.
`ifMissing` (the default Azure provider and model) only fills in keys a machine lacks, because Pi
saves the model you pick with `/model` there. `always` (the enabled models, and the packages
pinned to exact versions) wins on every run. Keys the file doesn't name, such as `theme`, stay
as each machine has them.

Packages: `@nuclear-ant/pi-code-blocks@0.1.2`, code blocks as bordered panels with a [Copy]
button. Reviewed at that version: no install scripts, no network calls, copies only through Pi's
`copyToClipboard` (wl-copy on Wayland). It patches Pi internals, so re-check it before raising
Pi's pin. Review any package's code before adding it here.

Not included, per machine: the Azure login. In `pi`, run `/login azure` and paste the API key,
then add the endpoint to that credential in `~/.pi/agent/auth.json`:

```json
"azure": { "type": "api_key", "key": "…", "env": { "AZURE_OPENAI_BASE_URL": "https://<resource>.openai.azure.com/openai/v1" } }
```

Also left alone: `extensions/herdr-agent-state.ts` (herdr installs it), `themes/` (Omarchy
generates it) and the `skills/` links into Omarchy.

## `_system-reference/`

Not a Stow package — just a copy of system-level (root-owned) config files for reference, since
Stow only manages `$HOME`. Currently:

- `etc/keyd/default.conf` — keyd config for Touch Bar Fn-key handling (see
  `~/omarchy-macbook-fixes/02-touchbar.md` for context). Apply manually on a new machine:

  ```bash
  sudo cp _system-reference/etc/keyd/default.conf /etc/keyd/default.conf
  sudo systemctl restart keyd
  ```

## Bootstrap on a new machine

```bash
sudo pacman -S --needed stow git
git clone https://github.com/xavidiaz/dotfiles.git ~/dotfiles
cd ~/dotfiles
./install.sh
gh auth login
```

CodeSpaces (`ssh cs-<name>`, `tuios attach --host cs-<name>`): the `codespaces` package has the
space entries but deliberately no address, since this repo is public. Give each machine the
address once, in a private file that is never committed, and include both:

```bash
printf 'Host cs-*\n  HostName <tailnet IP of the CodeSpaces host>\n' > ~/.ssh/config.d/codespaces-host
chmod 600 ~/.ssh/config.d/codespaces-host
# first line of ~/.ssh/config:
#   Include config.d/*
```

`install.sh` starts with a full `omarchy update -y`, so the packages it adds never land on an
out-of-date system (a partial upgrade). Run it in a real terminal: the update and some steps
ask for your sudo password. It then runs `stow` for every package, backing up any real (non-symlink) files already
in the way under `<file>.pre-stow-backup` instead of overwriting them — same as we had to do here
for `mise/config.toml`, which gets regenerated by mise itself if missing.
